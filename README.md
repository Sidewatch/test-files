# Sidewatch Test Files

The test corpus for [Sidewatch](https://github.com/Sidewatch), a native macOS review cockpit for terminal AI
agents. Its headless harnesses and by-hand checks run against these files. Nothing here is built or shipped;
every file exists to exercise one part of the app — a language's highlighting, a preview surface, a structure
tree, a gallery edge case — at a known size.

It is public so anyone can use it to test an editor, a highlighter, a previewer or a file-type detector:
219 languages with a complete syntax showcase each, a fixture for every structured config format, every
common media and archive kind, broken files, and 200,000-line sources.

## Using it

Clone it next to the Sidewatch app repository, which refers to it as `../TestFiles`:

```sh
git clone https://github.com/Sidewatch/test-files.git TestFiles
```

Then, from the app repository, the checks that read it:

```sh
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-highlight-roles ../TestFiles     # every language paints
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-config-views ../TestFiles/structured
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-gallery ../TestFiles/gallery
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-theme-sweep ../TestFiles
```

Or open any folder in Sidewatch (or press Space in Finder for Quick Look) and look.

## Layout

- `languages/<language>/` — one COMPLETE showcase per language the detector knows, named so the detector
  picks it from the name alone (`languages/swift/sample.swift`, `languages/makefile/Makefile`,
  `languages/zsh/.zshrc`). Each exercises every lexical and syntactic category its language has —
  every comment, string, number and literal form, every declaration kind, operator family, directive
  and embedded language — so highlighting can be checked at scale by eye, a folder at a time.
  `languages/picker-only/` holds the four whose extension collides with another language's.
- `samples/` — the small `sample.<ext>` files the harnesses assert on (Quick Look, `--dump-captures`,
  hover and completion built-ins, the outline), plus `template.php`, `test.md` and a `Dockerfile`.
- `previews/` — the preview surfaces: `people.csv` (table), `sample.db` (database browser),
  `sample.json` (JSON tree), `sample.png` (image), `example.zip` (archive), `page.html` (web),
  `sample-showcase.md` (every Markdown construct the preview renders).
- `large-files/` — `huge-200k.swift` / `.php` / `.js` / `.py`: 200,000 lines each of plausible code, the
  scale test for highlighting, folding, the minimap, sticky scroll and bracket matching. Generated
  (see the header comment in each); never hand-edit, regenerate.
- `editor/` — `gutter-check.swift`, `scrolltest.swift`: for checking the gutter and scrolling by hand (the gate's
  `--selftest-gutter` builds its own files).
- `structured/` — one fixture for every name the structure tree reads (its own README).
- `kinds/` — one file per non-code format the previews handle that the gallery does not, plus `requests.http`
  for the HTTP client (its own README).
- `sessions/<agent>/` — agent transcripts, at least one per adapter, for `Sidewatch --dump-session` and the
  Terminals rail's status derivation: `claude/` (three, written for the Timeline), `codex/` (two), `gemini/chats/`
  (`session-v040.jsonl`, the JSONL Gemini CLI writes since 0.40, and `session-demo.json`, the single-document form
  from before it) and `grok/` (`session/` and `subagent/`, each a `chat_history.jsonl` beside its `summary.json`).
  The Gemini 0.40 and Grok transcripts are sanitized captures of real runs, under the MIT licence noted in
  `NOTICE.md`.
- `themes/vscode/` — two VS Code colour themes for the importer: a dark one in JSONC with every awkward form
  theme authors use, and a light one with no `type` (its own README).
- `gallery/` — the media-gallery fixture (20 Sep 2026): a folder Sidewatch opens as a gallery.
  Images generated by a CoreGraphics script (solids, gradients, noise, stripes, a checker) in
  PNG/JPEG/TIFF/GIF/HEIC/WebP/BMP at normal sizes plus the awkward ones — 1×1, 16×16, 4000×3000,
  a 3000×3000 noise PNG (slow to decode), a 2400×120 panorama and a 120×2400 tower, an alpha
  fade, an UPPERCASE extension, spaces and Unicode in a name — and the failure cases: a
  truncated PNG, an empty PNG, text named `.png`, a malformed SVG. Four SVGs (linear, radial,
  shapes + text, viewBox-only). Four short ffmpeg videos (mp4/mov/m4v, one with an audio
  track). Audio: synthetic sine/silence/pink-noise in wav/m4a/aiff/flac/mp3 across sample rates
  and channel counts (a 10-minute silence for the duration column), plus a handful of real
  recorded instrument pads and a stretching source. `nested/` and `nested/deeper/` hold ten more (five
  PNGs and a pad one level down, three JPEGs and a pad two down) for the Subfolders box; `notes.txt`
  and `manifest.json` are the non-media noise a gallery must ignore. The harness also writes a
  2 s ramping-tone WAV of its own for the waveform tile. 13 MB.
- `migrations/` — example migrations for the destructive-SQL marks (20 Sep 2026): the same
  clean-up written in raw SQL, Prisma, Rails, Django, Alembic, Knex and Laravel, each with the
  statements that ARE marked (DROP TABLE / COLUMN, TRUNCATE, DELETE and UPDATE without a WHERE, a
  type change, a missing down step) beside the ones that must NOT be (comments, a literal in an
  INSERT, a conditioned DELETE with its WHERE on the next line, DROP CONSTRAINT), a pg_dump that is
  one mark, a test file and a README that are never scanned. Open the commit that added them in
  History to see the marks; `sessions/claude/database-turn.jsonl` is a transcript whose first
  turn runs eight database commands, three destructive, and carries a three-item plan and a
  bill (usage on its first message), for the Timeline; `sessions/claude/tests-turn.jsonl` runs the
  Swift suite (passes) and the JS suite (fails) in one turn, pytest in the next, nothing in the last.
- `schemas/` — the same data model as a Prisma schema, a Rails `schema.rb` and Django models
  (20 Sep 2026), for the ER diagram (View ▸ Preview on any of them) and the structural schema
  diff (edit one: the Changes rail badge and the file's banner in All Changes say what changed).
