# Sidewatch Test Files

The test corpus for [Sidewatch](https://github.com/Sidewatch), a native macOS review cockpit for terminal AI
agents. Its headless harnesses and by-hand checks run against these files. Nothing here is built or shipped;
every file exists to exercise one part of the app — a language's highlighting, a preview surface, a structure
tree, a gallery edge case — at a known size.

It is public so anyone can use it to test an editor, a highlighter, a previewer or a file-type detector:
219 languages with a complete syntax showcase each, a fixture for every structured config format, every
common media and archive kind, broken files, and 200,000-line sources.

## Using it

Clone it next to the Sidewatch app repository, which refers to it as `../TestFiles`:

```sh
git clone https://github.com/Sidewatch/test-files.git TestFiles
```

Then, from the app repository, the checks that read it:

```sh
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-highlight-roles ../TestFiles     # every language paints
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-config-views ../TestFiles/data/trees
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-gallery ../TestFiles/media/gallery
Sidewatch.app/Contents/MacOS/Sidewatch --selftest-theme-sweep ../TestFiles
```

Or open any folder in Sidewatch (or press Space in Finder for Quick Look) and look.

## Layout

| Folder | What it holds |
|---|---|
| `languages/` | One complete syntax showcase per language |
| `data/` | Structured files: `trees/` (JSON, YAML, TOML, XML, plists, INI…) and `tables/` (CSV, Procfile, ssh config) |
| `media/` | Images, audio, video, fonts, documents, archives, and a gallery folder |
| `database/` | SQLite databases, schema files and migrations |
| `sessions/` | Real agent transcripts, one folder per agent |
| `large-files/` | 200,000-line sources for performance |
| `themes/` | VS Code colour themes for the importer |

- `languages/<language>/` — one COMPLETE showcase per language the detector knows, named so the detector
  picks it from the name alone (`languages/swift/sample.swift`, `languages/makefile/Makefile`,
  `languages/zsh/.zshrc`). Each exercises every lexical and syntactic category its language has —
  every comment, string, number and literal form, every declaration kind, operator family, directive
  and embedded language — so highlighting can be checked at scale by eye, a folder at a time.
  `languages/picker-only/` holds the four whose extension collides with another language's. The hosts,
  crontab and gettext showcases here double as record-table fixtures.
- `data/trees/` — one fixture for every name the structure tree reads (its own README), plus `sample.json`.
- `data/tables/` — `people.csv` for the CSV grid, and a `Procfile` and an `ssh_config` for the record tables
  (`--selftest-record-tables` opens and edits them, on copies).
- `media/images/`, `audio/`, `video/`, `fonts/`, `documents/`, `archives/` — one file per media, document and
  archive format the previews handle (its own README): every image and audio container, WebM, TTF / OTF / WOFF /
  WOFF2, PDFs, an HTML page and `sample-showcase.md` (every Markdown construct the preview renders), and every
  zip-shaped archive plus a tar. `--selftest-kinds` opens each through the real open path.
- `media/gallery/` — the media-gallery fixture: a folder Sidewatch opens as a gallery. Images generated by a
  CoreGraphics script (solids, gradients, noise, stripes, a checker) in PNG/JPEG/TIFF/GIF/HEIC/WebP/BMP at
  normal sizes plus the awkward ones — 1×1, 16×16, 4000×3000, a 3000×3000 noise PNG (slow to decode), a
  2400×120 panorama and a 120×2400 tower, an alpha fade, an UPPERCASE extension, spaces and Unicode in a name
  — and the failure cases: a truncated PNG, an empty PNG, text named `.png`, a malformed SVG. Four SVGs
  (linear, radial, shapes + text, viewBox-only). Four short ffmpeg videos (mp4/mov/m4v, one with an audio
  track). Audio: synthetic sine/silence/pink-noise in wav/m4a/aiff/flac/mp3 across sample rates and channel
  counts (a 10-minute silence for the duration column), plus a handful of real recorded instrument pads.
  `nested/` and `nested/deeper/` hold ten more for the Subfolders box; `notes.txt` and `manifest.json` are the
  non-media noise a gallery must ignore. 13 MB.
- `database/` — `sample.db` (the database browser) and the same database as `.sqlite`, `.sqlite3` and `.db3`.
  `schemas/` holds one data model as a Prisma schema, a Rails `schema.rb` and Django models, for the ER
  diagram and the structural schema diff. `migrations/` holds the same clean-up written in raw SQL, Prisma,
  Rails, Django, Alembic, Knex and Laravel, for the destructive-SQL marks: the statements that ARE marked
  (DROP TABLE / COLUMN, TRUNCATE, DELETE and UPDATE without a WHERE, a type change, a missing down step)
  beside the ones that must NOT be, and `dump.sql`, a Postgres dump whose `public.`-qualified tables must
  still draw.
- `sessions/<agent>/` — agent transcripts, at least one per adapter, for `Sidewatch --dump-session` and the
  Terminals rail's status derivation: `claude/` (three, written for the Timeline: `database-turn.jsonl` runs
  eight database commands, three destructive; `tests-turn.jsonl` runs passing and failing test suites),
  `codex/` (two), `gemini/chats/` (`session-v040.jsonl`, the JSONL Gemini CLI writes since 0.40, and
  `session-demo.json`, the single-document form from before it) and `grok/` (`session/` and `subagent/`, each
  a `chat_history.jsonl` beside its `summary.json`). The Gemini 0.40 and Grok transcripts are sanitized
  captures of real runs, under the MIT licence noted in `NOTICE.md`.
- `large-files/` — `huge-200k.swift` / `.php` / `.js` / `.py`: 200,000 lines each of plausible code, the scale
  test for highlighting, folding, the minimap, sticky scroll and bracket matching. Generated (see the header
  comment in each); never hand-edit, regenerate.
- `themes/vscode/` — two VS Code colour themes for the importer: a dark one in JSONC with every awkward form
  theme authors use, and a light one with no `type` (its own README).
